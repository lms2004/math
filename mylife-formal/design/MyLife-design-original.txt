核心思想：
为了什么：我的认识散在脑子、对话和资料里，会变、会忘，也会被 AI 理解歪；同一条信息还会在不同的报告、对话和文件里反复出现。需要一套能回到原始依据、看得出怎么变过来、每次只吸收新增信息的个人认知系统
目标：任何时候取到的都是我当前的认识：对的、最新的、不重复的；每句话都能追到原始依据，看得出是谁起草的

1. MyLife 由四层组成：原始依据层 → 世界模型 → 个人认知模型，以及负责处理链路的 Agent 维护层
    * 原始依据层保存现实进入 MyLife 时的原件，以及从原件中抽出、能逐条对回原件的事实；世界模型和个人认知模型保存我在每个时间点已经形成的认识；Agent 维护层把新的输入吸收进前三层，并记下每次是怎么处理的
    * 箭头是信息流动和引用的方向：认识引用依据，个人认知模型可以引用世界模型，反过来不行
    * 系统保存全部复杂性。正文的篇幅、分节和条数由内容决定；Agent 可以把分散的材料分析成完整的正文，但不为了缩短而压缩已有正文，也不丢掉我的条件和程度
2. 知识的单位是信息，不是文件：一份输入里的信息分别进入事实或认识；同一条信息来自十份材料也只存一份，多出来的只是来源；材料本身作为原件保留
    * 我说过的话一字不改，全部保留；每次对话都自动存下来，Agent 自己的回答只留精炼后的核心信息；我贴进来的材料（包括和别的 AI 的对话、AI 报告）和需要完整保留的 AI 稿子原样保存
    * 对话按段落标话题、和相关节点连起来，以后的分析能结合全部历史对话，不需要我重复说明
3. 结构不追求一次正确：内容随我的新表达更新，节点身份和版本历史保持稳定；分类和关联只是其上的组织方式，由 Agent 随内容增长调整
4. 谁起草都可以，只有我能拍板：AI 可以理顺我的话、起草新内容，也可以从我的对话、我认可的文章和我说过的话里，分析出我在某方面的认知和看法，写成完整的分析稿；我判断和纠正，比我自己从头写效果和效率都更好，所以 AI 分析是正文的主要来源之一
    * AI 大胆推测、尽量深入，每句标清程度：确定、推测、可疑；我判断推测对不对，比 AI 不敢说更有价值
    * 内容要有信息密度：每句都要改变或细化某个判断，不写对谁都成立的正确废话、重复和铺垫
    * 进不进正文由我决定；每句话永远看得出是谁起草的、靠什么撑着
    * AI 的话只能经我确认进入认识，不能直接成为事实
5. 核心数据和界面完全解耦：核心数据只表达原件、事实、认识，以及它们之间的出处、来源和引用，不为任何界面保存字段、排序、状态或标签
    * 界面、提醒和统计都是从核心数据推出的投影，可以随时替换，不能写回；界面自己的状态（阅读进度、上次打开时间、展开到哪一档等）留在界面里
    * 界面怎么组织和呈现不受核心数据限制：页面和空间（围绕一个话题或决定，把原件、事实、认识和外部数据摆在一起，可以无限嵌套、按详略展开）都只存装配，即放哪些内容、绑定哪些 id、怎么排，存在界面自己的仓库；同一份数据出现在几个地方，引用的都是同一个 id
    * 空间里要用的外部数据（行情、利率、汇率、新闻、地图、视频）也先取回存成原件、抽成事实，界面只读核心数据，不另存一份
    * 界面上的输入和对话里的话走同一条路：确认和纠正稿子、回答过目里的问题、改推算的假设、随手写一句，都经 MCP 写入；我写的话先存成我的话再走吸收链路，确认本身记入操作日志；界面不直接改事实和正文
    * 每个字段都要说得出它是吸收、追溯、去重或更新中哪一项必需的；说不出的不存，能推出来的不另存，作用相同的用同一种结构
6. 对 Agent 完全开放：所有内容（原件、事实、正文、历史版本、吸收记录、过目记录和操作日志）都交给 Agent 读取和处理，不设私密等级，不做遮蔽，不考虑访问安全；系统只保证内容对、新、不重复、可追溯，把 AI 的帮助用到最大


核心原则：
读法约定（下文据此省略，不再逐处重复）：
    * 拍板：下文凡没写明由 Agent 或程序做的决定和正文改动，都由我做
    * 只追加：原件、事实、对象表、节点的历史版本、吸收记录和操作日志只追加，不改写；更正、作废和撤销都是追加一条新的；我要求的删除除外（见原始依据层）
    * 只引用：认识用到事实、片段或其他节点时只引用，不复制；把我的话正式化为正文不算复制
    * 推出：标了“推出”的都不存，由程序从已存的数据算出

1. 世界模型和个人认知模型不是静态真相，而是由当前有效节点组成的 Current Model
    * 节点是可以单独引用、单独更新的认知单元，有稳定 id 和完整版本历史；一个节点回答一个问题，同一个问题只有一个有效节点；标题写明这个问题或它的答案，属于正文
    * 节点只存三项：状态（有效 / 结束）、来源（由哪些节点分裂或合并而来）、版本
    * 每个版本记下写入时间、类型、有没有结论（认识 / 疑问）、理由和全部句子
        * 认知版本：认识本身变了，包括采纳 AI 起草的句子、倾向变了、疑问有了结论；必须附理由：我写的一句话、指向触发它的我的话，或者我对一份 AI 稿子的确认（确认本身就是理由，稿子和它用到的材料都记下来）
        * 整理版本：只整理表达，意思不变，不需要理由；改了哪些地方由程序对比上一版本列出（推出）
        * 新建节点是它的第一个认知版本，不需要理由
    * 增强、减弱、修改、得出结论都是同一节点的新认知版本；我自己的程度和把握写在正文中（“可能”“我比较确定”），不另设字段；AI 起草的句子另标程度（见核心原则 2）；疑问有了结论不新建节点，引用它的地方不会断
    * 分裂、合并由我的表达产生新节点，来源记下它从哪些节点来；节点不再成立或不再需要时结束，写一句原因（解决了、放下了、错了、被取代），退出 Current Model，历史保留
    * Current Model = 所有有效节点的最新版本 + 每条事实的当前值（推出）
    * 任意时刻的 Current Model 都能由版本、事实和操作日志的历史还原，以当时已写入的信息为准；事实的对应时间和写入时间分开；回看时引用取那一时刻的版本和值，正文明确写了引用某个历史版本的除外

2. 进正文的内容由我拍板，机器信息由 Agent 和程序维护
    * 正文：节点里我认定的内容；判断标准：改变“我认为什么、我打算怎么做”的是正文，只改变“内容如何被组织、连接、找到”的是机器信息（分类、关联、索引、吸收记录、操作日志）
    * 每句正文存文本和一个文字出处（原件中的一个片段），AI 起草的句子另存程度；句子的身份由出处和文本确定，不另设句 id；论证依据写成正文里的引用，可以有多条
    * 正文的三种来源由出处的作者和文字改动推出：
        * 原话：出处是我的话，句子就是其中的原文
        * 整理：出处是我的话，文字由 Agent 理顺过；只能理顺语序、删口语赘词、合并意思完全相同的重复、修正语病、调整格式和段落、把数字和事实状态换成对事实的引用；不增删观点、理由和条件，不改变程度和确定性（“可能”“感觉”“好像”保留），带强调或细微差别的重复保留，不把多条认识合并成一条，拿不准一律保留；整理只在一个片段内进行，不把两个片段的话合成一句，需要合并的写成几句，各有出处
        * AI 起草：出处是 AI 的话，经我确认；包括吸收时起草的句子和分析链路写出的分析稿；确认时稿子连同它依据的材料一起存为 AI 的话，作为这些句子的出处；我以后用自己的话改写（意思不变算整理版本），改写的话存为我的话并换成出处，就变回原话
    * 程度：AI 起草的句子都标程度，说明它的依据有多硬；Agent 起草时按下面的标准标，我确认时可以改
        * 确定：事实、我的原话或我明确针对这一点认可的片段直接说明了这一点；笼统的赞同、AI 的梗概、作者不明的稿子和转述，最高只能支撑推测
        * 推测：从依据推出来的，依据里没有直接说；鼓励大胆推测，包括我没说出口的假设、动机、盲点、前后不一致和看法的后果
        * 可疑：依据互相矛盾，只有单一或不可靠的来源（只有社区说法、只有 AI 说法、待核实），或和我以前说的不一致
        * 推测和可疑的句子经我确认后照样是正文，程度标记保留；我的原话和整理不标，程度就在我的话里
        * 推测的依据再多，也不会自动变成确定；Agent 可以在过目里就这一句直接问我，我明确认了就改标确定
    * 确认的方式：
        * 我直接写进指定节点、没经 Agent 改动的原话，写入即确认
        * 整理稿和 AI 起草稿都可以整篇确认：我只改不对的、删不要的，没动的句子算我确认；整理稿由程序列出被改动的程度词、否定词和语气（如问句改成了陈述句），AI 起草稿按程度标出推测和可疑的句子，加上问我的问题，我重点看这些
        * 决定的结论和承诺（我决定了什么、这个阶段怎么做、要守住什么边界）不随整篇确认，要我逐句确认
        * 我改的句子，改写的话先存为我的话，再作为它的出处；写入后随时可以对照出处，或恢复成出处原样（恢复也是一个新版本）
    * 正文的质量标准对所有来源一样：
        * 能单独看懂；说得具体（条件、适用范围、机制，数字引用事实）；有依据或标了程度；会影响我的某个判断或决定
        * 有信息密度：对任何人、任何情况都成立的正确废话（“投资有风险”“要结合自身情况”“各有利弊”）、重复前文、没有内容的铺垫、总结和客套都不写；宁可短而深，不要长而空
        * 讲事实的句子挂不上出处时，三选一：改写、标为可疑或不要
    * 引用：写在正文里，可以指向节点、事实或片段；正文是引用关系的唯一真源，引用索引由程序从正文推出；依据是支持、限定还是反对，用正文的话写明；正文脱离机器信息仍能完整理解
    * 事实和认识分开：事实记“谁说了什么”，认识记“我认为什么”；数字和事实状态只以事实为唯一真源，正文只引用不抄写
        * 由事实算出的数（如现金能撑几个月），正文写明用哪些事实、怎么算，值由程序推出
        * 推算用到的假设（汇率、月租、实习几个月）是我的估计，记为预期事实，出处是我的话；改假设就是追加一条新的预期接替旧的；我在界面上试着拖动、没要求保存的假设不存；结果不存，读的时候现算
        * 我的话里出现的数字，正式化时由 Agent 换成对事实的引用，事实里没有或对不上的，列出来给我
    * Agent 在对话里的分析不自动写回 MyLife：要成为正文，走分析链路，经我判断和纠正后写入；只想留作阅读材料的，作为 AI 的话存成原件

3. 每次输入只吸收新增的信息：每种数据都有明确的身份，同一身份只存一份
    * 身份：原件是内容哈希；片段是原文指纹；对象是对象表里的 id（名字和别名都指向它）；事实是对象 + 属性 + 适用范围（状态），或对象 + 事件 + 发生时间，有单号用单号（事件）；节点是它回答的问题
    * 来源按作者算：同一作者的多份原件重复同一说法，不算多个独立来源；转述别人的话，按被转述的人算
    * 同一身份再次出现：内容相同只追加来源或保存记录；内容不同才产生新值或新版本；拿不准是不是同一身份的不合并，交给我
    * 语义相似只用来找候选，不能单独作为合并依据
    * 事实拆到最小，论证保持完整：一段带前提、例外和结论的推理留在同一个节点的正文里，不为了去重拆成碎句


Agent 维护层：通过 MCP 接口吸收输入、分析认知、维护 MyLife
    为了什么：我只管表达、判断和纠正；拆解、对齐、去重、连接、分析起草、检查这些活由 Agent 和程序做，每一次处理都留下记录
    目标：任何输入进来，都说得清它的每一段产生了什么、或为什么什么都没产生；同一份输入处理几次结果都一样；我对某个方面的看法，可以由 AI 根据我给的材料分析出来，我判断和纠正后成为正文；任何内容进正文前都经过我

    含义说明：
    1. 三个角色：我（表达、判断、纠正和决定）；Agent（通过 MCP 接入的外部 AI，负责拆解、对齐、分析、起草、组织、检索，不需要理解底层文件）；MyLife 程序（MCP 服务本身，负责写入规则、数据检查、依赖列出和操作日志）
        * MyLife 本身不内置对话，也不包含界面；界面和提醒是读取核心数据的外部程序；界面上的写入同样经 MCP，规则和对话里一样（见核心思想 5）
        * 定期查看外部来源是 Agent 那边的定时任务，MyLife 不保存这类指令；查到的内容按“我要求保存”进入吸收链路
    2. 所有写入只走 MCP，经过同一套规则和检查，不论从哪里发起
    3. Agent 读的规则：Agent 可以读全部内容，没有读不到的地方；为了让上下文干净，默认先读 Current Model，核对、发现冲突或重新理解时，再回到片段和原件；AI 理解出错时，回到原件重新吸收，不依赖过去的 AI 总结或整理后的正文
        * 对齐和分析时读完整的历史：旧版本、作废的事实、撤销的关联、我不要过的稿子、我纠正过的理解，不再提出我已经拒绝过的内容，不再犯我纠正过的错误
        * 新对话开始时，Agent 按话题先读相关节点的当前版本（它们是以往对话的结晶）和相关事实，再读这些节点最近一版之后、还没被吸收进去的新对话，更早的对话按需检索；接着之前的内容往下谈，不需要我重复说明
        * AI 生成的报告、审计和批次情报吸收完以后，日常不再读它们，只作为原件保留
    4. 迁移旧数据：旧系统的文件当原件，按吸收链路重新走一遍
        * 作者按每段的内容判断（见原始依据层），不按旧文件上的来源标签；作者不明的旧稿，我可以整批确认
        * 旧的“写入口径”、卡片和页面同步说明属于旧界面，记为无信息
        * 旧系统算出的汇总数和 AI 的结论不进事实，从它们引用的原始导出、截图重新抽

    Agent 的边界：
    1. 自己做，事后可以撤销：保存我要求保存的原件、保存对话（随时可以保存到当前这一轮）、给对话分段标话题、新建和合并话题、切片段、取回 AI 给出的来源原文存成资料、抽取事实（对象明确、原文看得清、和当前值不冲突）、新建对象、给事实追加来源、按明确规则标出不同来源里的同一笔钱、给节点挂关联、分类、记下每个片段的处理结果
        * 只有这一档可以撤销（追加一条反向操作，抽取的事实就追加一条作废）；正文不能撤销，只能写新版本或结束；原件不能撤销，只能由我要求删除
    2. 一定问我（当场在对话里问，或作为稿子放进过目）：节点的新建、新版本和结束（稿子可以整篇确认，结论和承诺逐句确认）；事实冲突；关键事实有冲突又没有原文时，提议去取官方原文核实；抽取时拿不准的（看不清、有歧义）；两个名字是不是同一个对象、两条记录是不是同一件事、一条信息属于哪个问题；新的层内分类（话题除外）；做了就收不回的操作
    3. 不做：改原件、事实和历史版本；改动或精炼我的话；保存我没要求保存的内容（对话除外）；未经我确认把任何内容写进正文；在分析稿里替我在前后矛盾的说法中选一个；把 AI 的说法写成事实；在正文里写维护说明；没有我的指令自己去外面找信息（取回 AI 给出的来源原文除外）；代我执行现实中的动作（交易、提交申请、付款等）
    * 只做有明确标准的管理：不给内容打判断性的标签（紧急程度、重要性、是否成熟等）；AI 起草句子的程度按核心原则 2 的依据标准标，不算这类标签；只有身份和内容都相同的才自动当作重复；新信息由 Agent 对照已有内容起草，结构上的牵连（谁引用了变化的东西）由程序列出，是否过时、冲突或受影响都由我判断

        │   ├── review/        过目：等我拍板的稿子和问题；不是真源；处理过的稿子归档，采纳的已写进正文，不要的留作记录；纠正记录（过目里和对话里我对 AI 理解的纠正和要求）也放在这里；Agent 不再重复提出被拒绝的内容，不再犯纠正过的错误
        │   ├── links/         分类（含定义，变更保留历史）和关联
        │   └── log/           操作日志
        └── runtime/           可随时删除重建：索引、embedding、引用索引、界面投影和统计，从不当作真源

        * 界面的装配（页面和空间放哪些内容、绑定哪些 id、怎么排）存在界面自己的仓库，不在 mylife/ 里；runtime 里的界面投影只是缓存
        * 节点在世界模型和个人认知模型之间调整时只移动位置，id 不变，移动记入操作日志
        * 分类有两种，调整都不移动文件、不改正文、不产生新版本，分错没有后果：
            * 话题：跨层通用，按领域和对象划分（如“留学·选校”“投资·海油”）；节点、原件、对话的段落都标话题，按话题就能把相关的对话、事实和认识一起取出来，界面的空间通常也按话题取数据；Agent 自己建、合并和调整
            * 层内分类：世界模型和个人认知模型各自的初始分类（见各层），以及作者的类型（亲身、朋友、官网、社区、媒体…）；新增要问我
        * 关联：Agent 挂的，只表示相关，可以连片段和节点、节点和节点；片段挂到节点上就是这个节点的依据候选；我可以把关联写成正文里的引用，或撤销，撤销后记下，不再重复挂
        * 操作日志：每次写入、被检查拦下的写入、我处理过的过目事项（含冲突裁决和“确认不用改”）、撤销、时刻标记；只记 id、位置和动作，不抄写内容；用来核对、撤销和还原


    吸收链路（任何输入从哪来、写到哪）：
    1. 收件：我要求保存的话、文件、文章、AI 的话，以及每次对话 → 存成原件；同样的内容再存只追加保存记录；切成片段，逐段标作者，带稳定定位
        * 文本和已处理过的片段相同的，直接记为重复，不再抽取；每次出现仍保留在各自的原件或保存记录里，出现了几次可以推出；对话里的轮次不按文本去重：同一句“对”，针对的内容不同
        * 对话的身份是对话 id：同一次对话可以随时保存，多次保存只追加新的轮次；需要用我刚说的话作出处时，先把对话保存到这一轮
        * 我在对话里说的新想法、我直接写的正文，也先存成我的话，再走这条链路；没有不经过原件的写入
    2. 抽取：Agent 逐段找出能独立成立的信息，每条记下出处片段、说的是哪个对象、内容、适用条件（时间、范围、例外、否定、不确定性）、是谁的说法（我自己的、我转述别人的、AI 的）；逐段做完再整篇复核一遍：后文对前文的限定、跨段的数字和条件、依赖脚注的说法，合并成一条带完整条件的信息
        * 处理单位可以小，确认单位要足够大：一句话可以有两条信息，一整段也可以只是一个不能拆开的论证
        * 对话里我对 AI 说法的回应，按它针对的内容理解：明确针对某一点的赞同（“对”“就是这样”）等于认可那一点；笼统的赞同（“有道理”“认知更深刻了”）只算认可大意；反对等于我说了相反的看法
        * 我对 AI 理解或分析方式的纠正和要求（如“我不是想躺平”“不要说得这么抽象”），除了照常吸收，另记一条纠正记录，和分析链路里的纠正放在一起，Agent 每次分析前先读；意思相同的纠正合成一条，带上每次的出处，出现次数越多说明对我越重要；纠正记录带话题，只对某个话题有效的（如“投资分析必须给具体点位和概率，不许用观望搪塞”），只在这个话题下读
        * 同一次对话里，我后面的话修正了前面的，以修正后的为准，前面的只作为演变过程；只是补充的，合起来理解
        * 时间说得模糊的（“上周”“月底”），按原件的时间换算成范围，不猜具体日子
        * 原件本身没有时间的（如贴进来的对话没写日期），按保存时间记并标“时间不明”；跨对话比较先后时，时间不明的不算修正，按矛盾问我；两边时间都明确的，后面的是现在的看法：起草新版本，标出“看法变了”，变化本身写进分析
        * Agent 把内容复述给我、我明确确认的（“确定”“对”），复述的内容算我的说法，可以进事实；出处同时指向复述和我的确认
        * 我的请求本身不产生事实或认识，但反映我在做什么；同类请求反复出现时（如同一天五轮“全量深挖”），挂到相关的运行方式节点作依据
    3. 分流：每条信息按性质去一个或几个地方
        * 数据：数字、日期、状态，以及交易、提交、成绩这类可以计数的事件 → 事实；AI 的说法不进事实，片段记为待核实，附上 AI 给出的来源（网址，或我自己存过的原件，如旧笔记里写的聊天记录、文件路径）；Agent 先在我的库里找，再去取网址，取回的存成资料，再从资料抽事实，取不到的保持待核实
        * 叙述、观察、经历 → 不另存，片段挂关联到相关节点，作为依据候选
        * 解释、机制、判断 → 认识：去掉“我”这句话还成立的进世界模型（如“港大的 CS 比港中文强”）；离开我就不成立的进个人认知模型（如“港大更适合我”“我容易用做项目逃避主线”）；AI 对我的建议也进个人认知模型；同一句话可以两边都去：讲世界怎样运行的进世界模型（“风险无法消除”），讲我因此怎样选择的进个人认知模型的原则（“我做决定前先接受最坏结果”）
        * 对话里 AI 说的、我没有表态的内容 → 不起草，只作为材料留着，分析时可以用；但我请 AI 分析我自己（“总结一下我这样的人”“结合我的特点分析”）得到的回答，作为分析稿进过目，由我判断
        * 没有信息量（寒暄、过程描述、重复铺垫）→ 只留原件
    4. 对齐：按身份和已有内容比较，决定每条信息的去向
        * 事实：
            * 同一身份、同一作者、同样的值 → 重复
            * 同一身份、新的作者、同样的值 → 追加一条来源
            * 同一身份、同一作者、新的值 → 追加，接替旧值
            * 同一身份、不同作者、不同的值 → 追加并标出冲突，交给我
            * 新的身份 → 新增；对象表里没有的对象直接新建，和已有对象名字相近的交给我
            * 没有单号的事件，和已有事件对象、时间、金额都接近的，交给我判断是不是同一件事
        * 认识：
            * 意思已经在某个节点里 → 片段挂关联到这个节点，不出版本
            * 补充了条件、反例、理由、程度，或改变了倾向、结论 → 起草新版本稿；拿不准是已有还是补充，按补充处理
            * 和已有节点相反 → 起草新版本稿，标出相反之处
            * 新的问题 → 起草新建稿；只为会影响我判断或决定的问题建节点，顺口一问、我自己也没有倾向的，挂关联到相关节点或只留原件
            * 拿不准属于哪个问题 → 列出候选节点，交给我
            * 一个节点同时只有一份待定稿子：同一次吸收里指向同一个节点的候选合成一份；过目里已经有这个节点的待定稿子时，新的候选并进去重新起草
    5. 覆盖检查：程序检查每个片段都有处理结果：产生了什么（事实、关联、稿子），或为什么什么都没产生（重复、无信息、待核实、跳过、未处理）
        * 跳过是我指定不吸收的部分；未处理是 Agent 没能抽出来的，原件留着，不算吸收完
        * 相关的决定已经结束的大批材料（如放弃考研后剩下的考研报告和数据包），Agent 提议整批跳过；原件留着，需要时再吸收
        * 长材料由 Agent 只用吸收结果反查原件的核心问题，答不出来的说明可能漏了，标回未处理；尤其核对数字、否定、时间边界、适用对象、反例和因果链
    6. 写入：事实按第 1 档直接写；节点的稿子放进过目，我整篇确认，只改不对的、删不要的（结论和承诺逐句确认），确认的写入；吸收记录、数据变更和操作日志一起提交
        * 没有新信息的输入，记一次“无变化”的吸收即可，不为了有变化而写东西
        * 同一份输入再处理一次，已有结果的片段不再产生任何东西，除非这次找到了上次漏掉的信息并经过对齐
        * 稿子记下它基于节点的哪个版本；节点之后有了新版本，我选重新起草或不要，不直接写入
        * 可以一次指令同时保存和正式化（如“把这段存成一条世界认识”）；过目的稿子可以积攒起来批量处理
        * 同一次吸收或分析产生的多份稿子作为一组过目，可以整组确认；组里每个节点仍各自成版本
        * 过目里问我的问题，之后的材料里我已经回答了的，Agent 标为已回答并附上出处，不再问我
    * 重新吸收（发现 AI 之前理解错了）：对同一份原件追加一次新的吸收记录；它之前产生的事实先作废再重新抽取，关联重新挂；正文不动，出处在这份原件里的节点列出来给我


    分析链路（AI 分析我在某方面的认知，我判断和纠正）：
    1. 起点：我指定一个方面或问题（如“我对海油的看法”“我现在怎么看选校”），可以附上材料（一段对话记录、几篇我认可的文章、一些我说过的话）；某个节点挂上了较多新依据时，Agent 也可以提议重新分析
    2. 取材：我附上的新材料先走吸收链路存成原件；Agent 再收集和这个方面相关的全部材料：我的话（按话题分类和关联取出相关的历史对话，含钩子）、我认可的片段、相关事实、已有节点的当前版本和历史，以及我以前纠正过的理解和不要过的稿子
    3. 起草：Agent 写一份完整的分析稿，作为新节点或已有节点的新版本；可以重新组织结构、补上推理、得出结论，篇幅由内容决定，用我的口吻写我的看法
        * 大胆推测、尽量深入：不只复述我说过的，还要推出我没说出口的假设、动机、盲点、前后不一致，以及这些看法会带来的后果；每句标程度，能引用的依据都引用
        * 重要的结论写全：依据、推理链、成立的条件、反方证据，以及出现什么情况会推翻它；推翻条件尽量写成能和事实对照的条件（如「实际利率回到 2.2% 以上」），现在的值由程序从事实推出，到了就进过目
        * 跨对话的矛盾、同一对话里没有修正过的矛盾、或材料不够判断的地方，不替我选，写成问我的问题，附上各自的出处；同一对话里已经修正过的，以修正后的为准，不再问
        * AI 自己补充的分析（如行业、估值、风险判断）同样标程度，数字引用事实
        * 写完自查一遍密度：删掉对谁都成立的话、重复、铺垫和总结；我以前删掉过的那类话不再写
        * 按“去掉我是否还成立”分到世界模型和个人认知模型；一份投资分析通常拆成对标的的判断（世界）和我的持仓决定（个人）；覆盖几个问题时，Agent 提议拆成几个节点
        * 已有节点的重新分析，和当前版本逐处对比，列出哪些判断变了
        * 出处是我的话的句子（原话和整理）原样保留；新材料和它们矛盾时，单独列出、附上依据，由我决定改不改，不在重写中顺手改掉
    4. 判断和纠正：我整篇看，重点看推测、可疑、问题和变了的判断；对的不用动，不对的直接说正确的是什么，不要的删掉，问题用我的话回答；决定的结论和承诺逐句确认
    5. 写入：分析稿连同它用到的材料清单存为 AI 的话；我没动的句子作为 AI 起草写入，出处是这份稿子；我纠正和回答问题说的话存成我的话，纠正过的句子出处换成我的话；确认本身就是这个版本的理由
        * 重新分析没有改变任何判断、只是重新组织的，作为整理版本写入，不触发引用者
        * 我纠正和回答问题说的话同时进入吸收链路，可能补充别的节点
        * 我纠正过的理解归档在过目记录里，Agent 以后分析时先读


    更新的传播（一处变了，别处怎么办）：
    1. 信息只从依据流向认识；认识变了不回头改依据：我改变想法时说的话本身作为新原件存进依据层，成为新版本的出处和理由
    2. 引用的东西变了，引用者进过目：被引用的节点有了新的认知版本或结束、被引用的事实当前值变了，程序列出直接引用它的节点，问我要不要跟着改，不自动起草；我改了或确认不用改，记入操作日志，这条引用就算跟上了（推出）
        * 整理版本、追加来源和挂关联不触发
        * 只列直接引用者；我改了某个节点后，再由它的引用者接着收到，一层一层传
    3. 正文引用的事实和由事实算出的数，读的时候自动取当前值，不产生新版本
    4. 世界模型的变化可以牵动个人认知模型，个人认知模型的变化不牵动世界模型
    5. 认识之间只提醒，不自动改写


    记录与检查：每次写入记入操作日志（时间、谁、动了哪些 id、依据的指令）；正式写入前由程序检查，不合规就拒绝并告诉我；成功的数据变更、吸收记录和操作日志一起写入
    * 只追加的内容没被改写；id 唯一；同一身份只存一份
    * 每个片段都有作者和处理结果；每条事实和每句正文都有出处，出处指到存在的片段
    * 对话里我的每一轮和客户端导出的原文逐字一致（转录的标出）；精炼稿都标明是精炼
    * 重新分析没有改动出处是我的话的句子，除非我单独决定
    * 事实的对象在对象表里；事实的出处不是 AI 的话
    * AI 起草的句子都标了程度；标为确定的至少引用一处直接依据
    * 正文只经我确认写入；认知版本都有理由；决定的结论和承诺经过逐句确认；整理稿和原话逐处对比，列出被改动的程度词、否定词和语气
    * 世界模型不引用个人认知模型
    * 分类先登记再用


原始依据层（Evidence）：我真正说过、看到、经历、拥有过什么
    为了什么：认识会变、AI 会理解错，必须有一份不会变的原始记录可以回去重读；数字和事实状态需要一个唯一的来源
    目标：我要的东西都能原样找回；每句正文、每条事实都能追到原件的具体位置；同一份东西只存一份

    含义说明：
    1. 保存我要求存入的内容、我和 Agent 的每次对话，以及 Agent 为核实 AI 说法取回的来源原文；它是当时的原始记录，不等于客观真相；除了我的话，其余都不代表我的认识
    2. 保留原始：原件始终保留，只追加不改写；吸收完也不删原件；唯一的例外是 Agent 在对话里自己的回答，只存精炼稿（见核心内容）
        * 转写、OCR、PDF 抽出的文字是派生文本，附在原件上，带页码或时间等位置标记；有误只更正派生文本，已被引用的旧文本及其定位保留
        * 拿不到原件时（网页没能另存、只抄下一段），存为摘录，写明从哪摘、为什么没有原件
        * 二进制原件（图片、PDF、音视频、压缩包）放在仓库外的原件库，Git 里只记哈希和位置；原件库有备份，程序定期按哈希校验原件还在、没被改动或损坏，有问题的记入操作日志
        * 删除：我要求删除某份内容时（存错了、不想要了），程序列出含这段内容的所有地方（派生文本、事实、正文句子和它们的历史版本、过目记录、runtime 的索引和 embedding、Git 历史和备份），我逐项决定一起删除还是保留；删除的只留删除记录（不含原内容）
    3. 同样的内容只存一份：按哈希存；再存只追加一条保存记录（时间由程序记、名字、从哪来、来源地址、覆盖范围：如导出覆盖的时间段、是否完整）；压缩包整体存一份，包里的目录由程序读出（推出），成员不另拷
    4. 片段：原件切成片段，是出处和吸收记录的最小定位单位；每个片段有稳定定位（原件哈希 + 位置 + 原文指纹）：文本到段落，PDF 到页，图片和表格到区域或行，音视频到时间段，压缩包先定位到包里的文件；重新解析不改变已被引用的定位
    5. 作者：每个片段标出作者：我、AI，或外部发布者（某个官网、账号、媒体、个人）；我的话、AI 的话和外部资料不存在同一段里；作者用来判断说法是谁的、几个来源是不是独立的
        * 作者按每段的内容判断，不按文件上的标签：一份文件里常常同时有我的原话、贴进来的外部内容和 AI 的整理
        * 我的一段话里贴了外部内容（网页、门户页面、别人的报告），贴进来的部分单独成段，作者是那个来源
        * 看不出作者的（用第一人称写、但可能是 AI 用我的口吻整理的稿子），以及 AI 转述我的话、原话已经不在的（“原意保留”），标为作者不明或转述：不能当原话，用它支撑的句子最高标推测；我可以整批确认，确认后算我的话

    核心内容：
    1. 原件（sources/）
        * 我的话：我要求保存的话、直接写的话、日记、随手记、原始笔记，以及钩子
            * 钩子：保存或重读时，我对某个片段写下的感受（哪里打动我、为什么值得回来看），只标“认可这一段”也算；钩子指向它挂的片段，每次重读都可以追加；我认可一段，说明它接近我的想法，所以认可的片段是分析我看法的重要依据，也可以被我引为版本理由；要让它成为我的认识，经分析链路或在过目里确认
        * 资料：我拿到的原始资料，不论来自自己还是外部：图片、截图、文档、成绩单、简历、合同、申请材料、财务导出、官网、政策原文、财报、论文、新闻、研究报告、网页、社区内容等
        * 对话：我和 Agent 的每次对话自动存成一份原件，按轮次记下作者和时间
            * 由 Agent 所在的客户端原样导出交给 MyLife，不经模型重打；同一次对话可以随时保存，多次保存只追加新的轮次
            * 我的每一轮原样保留，一个字不改，包括很短的回应；拿不到原样导出、只能由 Agent 转录的，标为转录
            * Agent 的每一轮存成精炼稿：留下结论、关键理由、数字和它给出的来源地址、建议、问我的问题，以及我下一轮回应所针对的内容，让我的话离开原对话也看得懂；删去寒暄、重复、铺垫、格式和对谁都成立的废话；精炼稿标明是精炼，不是当时的原文；我说要完整保存的那段，原样存
            * 我在对话中贴进来的材料（文件、文章、和别的 AI 的对话或报告）是我主动给的，各自原样存成原件，不精炼，对话中只引用
            * 贴进来的对话记录（包括别的 AI 整理好的“原话 + 精炼”文件）按对话拆分作者：我的轮次作者是我，不是平台原样导出的标为转录；AI 的轮次作者是 AI；整理者加的梗概、归纳、总结作者也是 AI；内容原样保存，不重新精炼
            * 梗概：AI 对原文已经拿不到的内容写的概述（如“更早的对话只剩梗概”），存为 AI 的话并标“梗概，无原文”；它不能作为原话的出处，用它支撑的句子最高标推测
            * 对话按段落标话题（一次对话常谈几件事），对话本身带上全部话题，并按涉及的节点和对象挂关联，再走吸收链路；吸收出的稿子积攒在过目里，不打断我
        * AI 的话：我要求完整保存的 AI 报告和分析、我贴进来的和别的 AI 的对话，以及我确认写进正文的 AI 稿子，整段原样存，每段记下作者，附上当时的上下文（比如我的问题）；它只是材料，要成为我的认识必须经我确认（走分析链路或在过目里确认），里面的数据要成为事实必须先取回原文
    2. 事实（facts/）：原件的结构化摘录，只记原件里明说的数据；记的是“谁说了什么”，不是“我信什么”
        * 出处只能是资料或我的话；每条都能对回原件，抽错了作废重抽，原件不受影响
        * 对象：事实挂在对象上（一个项目、一份申请、一个账户、一只股票、一件物品、一个决定、我自己）；对象表记下每个对象的名字、别名，以及我定下的某些属性以哪个作者为准；同一对象只有一个 id；没有名字的对象，Agent 按描述起名（如“每周两次组会的那门本科课”），我之后可以改名；付款记录里的对手方名字（如“好运连连”）也是对象的别名
        * 我对一批事件的归属或分类（如“滴滴入账都是我爸的收入，借我的账户代收”）记为事实，作者是我，适用范围写明是哪一批（对手方、时间段）
        * 未来的数（预计到账的支持、预计收入）记为预期，标明预计时间和我说的确定程度；到账后由实际的事件接替，不算冲突
        * 同一笔钱在不同来源里各有一条（如京东订单、微信付款、支付宝流水），各自保留，标为同一笔，算总数时只算一次；能按明确规则对上的（金额一致、时间相近、商户对得上）自动标，拿不准的问我
        * 我直接说出的汇总数（如“净资产 17.8 万”）也是事实；和由明细算出的数不一致时，两个都保留，列出来给我；算总数时，覆盖不全的原件（导出不完整、只到某个日期）对应的部分要标出来
        * 两种形式：状态（某个对象的某项属性在某时的值，如学费、持仓、申请状态、截止日、持有物）和事件（某个对象在某时发生的事，如交易、提交、面试、发 offer）
        * 外部的数据序列（价格、利率、汇率、指标）按观察时间各记一条状态，作者是发布方，原件是每次取回的导出或页面；同一作者同一观察时间的同样值只记一次；当前值是最近一次观察，走势由这些状态推出
        * 每条记下：对象、属性或事件、值、适用范围、对应时间（状态成立或被观察到的时间，事件的发生时间）、出处（指到原件的某个片段、某一行或某个区域，不指到摘要或 AI 分析）
        * 值可以是范围或约数，照原话的确定程度记（“十几万”记为约 10–20 万；“可能 20 多万”记为约 20 多万，标“我的估计”），不替我精确化
        * 同一条事件即使来自两份时间重叠的导出也只记一次；同一份原件的同一类事实只抽取一次，重新抽取先作废旧的
        * 状态的当前值（推出）：同一作者的新值接替旧值；定了以哪个作者为准的属性，这个作者的新值直接接替；其余不同作者给出不同的值时标为冲突，当前值保持不变，交给我：采用新值，或作废其中一条（追加作废记录），同时可以定下这项属性以后以哪个作者为准（如持仓以券商导出为准），以后不再为同类情况问我；裁决记入操作日志
        * 我自己定下的日子（计划在哪天前做出决定、哪天复盘、这个阶段预计到哪天）也记为事实，出处是我的话；正文引用它，界面可以据此提醒
        * 外部资料里的判断性说法（如“某项目通常两周内发 offer”）也可以记为事实，但它只是“作者 S 称……”，不等于我相信；我采信什么，写进世界模型


世界模型（World Model）：我对外部世界的认识
    为了什么：把我对外部世界的认识单独保存、单独更新
    目标：任何时候都能取到我对某个外部问题当前怎么看、靠什么撑着、怎么变过来的

    含义说明：
    1. 我当前认为这个世界是什么样、为什么这样运行；不是我的都属于外部世界，包括家人和他人、组织和行业，以及小说、电影、动画等作品
        * 判断标准：去掉“我”这句话还成立，就属于这里
        * 我对家人的认识在这里；家庭给我带来的处境在个人认知模型
    2. 这里保存我已经形成的认识；阅读材料和外部的说法（项目信息、行情、政策条文）留在原始依据层，通过引用连接；事实记谁说了什么，我采信什么写在这里
    3. 一个节点回答一个外部问题；正文可以是完整的论证：前提、机制、例外和结论放在一起，不拆散
    4. AI 起草最适合这一层，包括完整的分析稿（如某个投资标的的基本面、定价、情景和风险分析）；我认同的部分确认为我的认识，不同意的直接纠正；AI 起草的句子标程度（确定、推测、可疑），我自己的把握写在正文里
    5. 疑问：还没有结论的问题也是节点，正文写各种解释、依据和当前倾向；倾向的变化就是版本变化
        * AI 可以起草候选解释；能直接查证的，取回原文存成资料，抽成事实
        * 倾向写在正文里；几个候选各占几成，可以写成正文里的一张表，界面据此画图，不另存比例
        * 有了结论就是同一节点的新认知版本，由疑问变为认识；不再想了就结束，写明放下了
    6. 世界模型只引用原始依据层和其他世界节点，不引用个人认知模型

    初始分类（Agent 维护，随内容增长拆分或新增，如职业、教育、投资、作品）：
        人与社会、组织与制度、经济与资源、技术与信息、系统与风险、未分类


个人认知模型（Personal Model）：我对自己的认识
    为了什么：理解我是怎样的、为什么走到这里，并把这些认识落到当前该怎么做上
    目标：任何时候都能取到我现在的处境、主线、在用的做法和还没定的决定

    含义说明：
    1. 结合直接经历、自我观察和世界认知，理解“我”，以及我怎样选择和生活；可以引用原始依据层和世界模型
        * 判断标准：离开我这句话就不成立，就属于这里
    2. 这一层主要的写法是 AI 分析：我提供对话记录、认可的文章和说过的话，AI 分析我在这方面的认知和看法，起草正文，我判断和纠正（见分析链路）
        * AI 可以大胆推测我的想法、动机和盲点，每句标程度；推测和可疑的由我重点判断
        * 决定的结论和承诺（我决定了什么、这个阶段怎么做、要守住什么边界）要我逐句确认
    3. 节点结构和世界模型完全一样；下面的分类只用于组织和检索，不带任何字段，分错没有后果，节点可以随时换分类
    4. 日级待办、打卡和日程提醒交给外部工具，不进核心数据；需要的数字和状态（花费、持仓、申请状态、截止日、持有物）记在事实里，正文只引用
        * 界面里的待办、打卡和日程属于界面自己的数据；打卡时我写的话照样存成我的话；要拿来当依据的统计（如两周断了几天），由我要求保存：界面导出的记录存成原件，再抽成事实


    核心分类（初始，Agent 维护）：

    1. 当前处境：我现在走到了哪里，有哪些核心问题
        * 由多个节点组成，各自独立更新；初始分类：现实与财务、学业与申请、关系、家庭、作息与身体、心理、持有
        * 还没解决的问题各是一个节点，包括历史遗留问题；解决了就结束，原因写“解决了”，历史保留；不追求清零
        * 当前已经表现出来、且与处境相关的个人特征也写在这里

    2. 经历与成因：我为什么走到这里，这些问题是怎么形成的
        * 关键经历、转折、成功和失败，以及我对成因的认识；深度复盘在这里完成，其他节点只引用
        * 经历本身的原始叙述留在原件里，这里写我对它的理解，并引用那些片段

    3. 运行方式：我实际上是怎样运行的
        * 某个特征在不同处境和经历中反复出现、且我认为会持续时，写在这里；否则留在当前处境中；同一特征在第二个领域或第二次对话里出现时，Agent 提议移到这里

    4. 原则：我依据什么做选择
        * 相对稳定的选择标准，不分等级；长期方向也是原则
        * 和运行方式的区别：运行方式描述我实际怎样运行，原则是我选择怎样做

    5. 阶段与做法：这个阶段我在怎么做
        * 阶段：一个阶段一个节点，正文写这个阶段的主线、在推进的事（引用处境里的问题和要做的决定）和在用的做法；进入新阶段时写新节点，来源指向上一阶段，上一阶段结束；约定任何时刻只保持一个有效的阶段节点
        * 做法：在什么情况下我怎么做，包括事前守住的边界和事中的处理方式；一个做法一个节点，可以被多个阶段引用；AI 可以起草做法，好不好用写在正文里
            * eg. 针对“容易通过做项目逃避当前主线”，事前边界和已经陷进去之后的处理各写一个做法
        * 对未来的预想写成疑问，各个可能的状态是它的候选解释；预计到哪天记为事实，正文引用；到了那一步，我写出实际的阶段（可以沿用某个候选，也可以是新的），这个疑问写上结论

            阶段 (2026.9.15，当前)    -> 做法一 / ... / 做法 N
                                     -> 疑问：2026.12.15 之后我会走到哪一步
                                            候选：状态 A -> ... 做法 N ...
                                                  状态 B -> ... 做法 N ...
                                                  状态 N

    6. 关于自己的疑问和要做的决定：还没有结论的问题，按世界模型中疑问的方式保存
        * 要做的决定是关于自己的疑问：正文写方案、分析、实验、假设、暂时判断和当前倾向（可以给方案分层或排序）
            例如：
                1. 留学选择学校 -> 学校优势
                2. 职业规划 -> 去大厂还是去国企
                3. 是否应该买房
                4. 投资 -> 资产配置和买卖取舍
        * 我写下结论时形成新的认知版本，由疑问变为认识，节点保持有效；结论带来的认识变化更新到相关节点；之后改主意或做下一次具体决定（如资产配置的每次调整），继续写新版本
        * 涉及现实动作（交易、提交申请等）的结论由我亲手执行，结果作为事实记下
